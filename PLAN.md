# PLAN.md  
## План реализации GoNext — «Дневник туриста»

Документ описывает **поэтапный порядок действий** по воплощению `PROJECT.md` в рабочее приложение.  
Исходная точка: уже есть Expo SDK 54, Expo Router, React Native Paper и экран Home.

Вне MVP (PDF, бэкап, синхронизация, совместные поездки, статистика, карта всего маршрута) в этот план **не входят**.

---

## Этап 0. Подготовка каркаса

1. Заменить текущий демо-экран Home на главный экран из ТЗ:
   - AppBar «GoNext»
   - вертикальный ряд кнопок: Места, Поездки, Следующее место, Настройки
2. Настроить навигацию Expo Router под основные разделы:
   - `/` — главный экран
   - `/places` — список мест
   - `/places/[id]` — карточка места
   - `/trips` — список поездок
   - `/trips/[id]` — детали поездки
   - `/next` — следующее место
   - `/settings` — настройки (заглушка на MVP)
3. Вынести общую тему PaperProvider / AppBar в корневой layout.
4. Проверить запуск на устройстве (LAN через hotspot / tunnel).

**Критерий готовности:** из Home открываются все разделы, даже если экраны пока пустые.

---

## Этап 1. Локальное хранилище (SQLite)

1. Подключить SQLite для Expo (например, `expo-sqlite`).
2. Спроектировать схему БД по сущностям:
   - `places`
   - `trips`
   - `trip_places` (связь Trip → Place + порядок, visited, notes, visitDate)
3. Реализовать:
   - инициализацию БД при старте приложения
   - миграции / создание таблиц
   - слой доступа к данным (repository / services)
4. Хранение фото:
   - каталог в файловой системе приложения (`expo-file-system`)
   - в БД — пути/имена файлов, не бинарные данные

**Критерий готовности:** приложение создаёт БД локально и умеет CRUD для Place и Trip без UI-полировки.

---

## Этап 2. Режим «Места»

1. Экран списка мест:
   - список из БД
   - пустое состояние
   - переход к карточке / созданию
2. Форма создания/редактирования места:
   - name, description
   - visitlater, liked
   - координаты `dd` (ручной ввод и/или выбор на карте позже)
3. Детальная карточка места:
   - просмотр полей
   - редактирование
   - удаление (с проверкой связей с поездками)
4. Фотографии места:
   - выбор из галереи / камеры (`expo-image-picker`)
   - сохранение файла локально
   - превью в карточке
5. Действие «Открыть на карте» по координатам (deep link).

**Критерий готовности:** можно полностью вести базу мест офлайн, с фото и открытием на карте.

---

## Этап 3. Режим «Поездки»

1. Экран списка поездок:
   - title, даты, признак `current`
   - создание новой поездки
2. Форма поездки:
   - title, description, startDate, endDate
   - назначение/снятие `current` (только одна текущая)
3. Экран деталей поездки (маршрут):
   - упорядоченный список `TripPlace`
   - добавление мест из базы или создание нового места «на лету»
   - изменение порядка (вверх/вниз или drag-and-drop)
   - отметка `visited` + `visitDate`
   - заметки `notes`
   - фото посещения (отдельно от фото Place)
4. Отображение поездки в двух «ролях»:
   - план (много `visited = false`)
   - дневник (посещённые места с заметками/фото)

**Критерий готовности:** поездка создаётся, наполняется местами, ведётся как план и дневник.

---

## Этап 4. Режим «Следующее место»

1. Определить активную поездку (`current = true`).
2. Найти первое место с `visited = false` по `order`.
3. Экран «Следующее место»:
   - данные места и контекст поездки
   - состояния: нет текущей поездки / все места посещены / есть следующее
4. Действия:
   - открыть на карте
   - открыть в навигаторе (Google Maps / системный)
5. Быстрая отметка «посещено» (опционально, удобно для MVP).

**Критерий готовности:** за один тап с Home видно следующее место и можно уйти в навигатор.

---

## Этап 5. Интеграция карт и геолокации

1. Подключить нужные модули (`expo-linking`, при необходимости `expo-location`).
2. Единые хелперы:
   - открыть точку на карте
   - построить маршрут в навигаторе
3. Проверить поведение **без интернета** (офлайн-кеш карт — ответственность внешнего приложения; в GoNext не падать).
4. При необходимости — подстановка текущих координат при создании места.

**Критерий готовности:** из Place, TripPlace и «Следующее место» стабильно открываются карта/навигатор.

---

## Этап 6. Настройки и полировка UX

1. Экран «Настройки» (минимум для MVP):
   - версия приложения
   - краткая справка / о приложении
   - при необходимости — сброс локальных данных (с подтверждением)
2. Единый визуальный стиль Paper на всех экранах.
3. Обработка ошибок БД и пустых состояний.
4. Проверка офлайн-сценария целиком на Android и iOS (Expo Go / SDK 54).

**Критерий готовности:** приложение выглядит цельно, не падает на пустых данных, работает без сети.

---

## Этап 7. Проверка соответствия MVP

Пройти сценарии из целей приложения:

1. Добавить несколько мест в базу.
2. Создать поездку, собрать маршрут, задать текущую поездку.
3. Отмечать посещения, писать заметки, добавлять фото.
4. С главного экрана открыть «Следующее место» и уйти в навигатор.
5. Убедиться, что после перезапуска данные на месте (локальная БД + файлы фото).

**Критерий готовности:** MVP из `PROJECT.md` закрыт; можно планировать пункты из раздела «Будущее развитие».
